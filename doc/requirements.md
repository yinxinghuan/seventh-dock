# 《Seventh Dock》需求文档

## 1. Overview

《Seventh Dock》是一款有状态 AI 驱动的竖屏连续小队冒险：玩家以自己的 AlterU 身份进入不断涨潮的港城，通过对话、调查、检定和资源取舍推进世界。单次游玩目标为 8–12 分钟，但故事不按固定轮数结束，可跨日、跨设备恢复。

核心情绪承诺：世界会记得玩家救过谁、怀疑过谁，以及为了继续前进付出了什么。

主界面只有一条按时间向下生长的剧情流、底部快速回复/自由输入，以及一个收纳人物、地图、背包和日志的“World / 世界”抽屉。支持完整 zh/en 内容；首次语言来自调试覆盖、存档或系统语言，明确使用另一语言回答时自动切换后续界面与回复，历史记录不重写。

当前 AlterU 用户是故事主角。玩家行动与人物页显示其用户名和头像；关键剧情生图可引用公开 HTTPS `head_url`，但头像资料不写入故事存档。

## 2. Visual Design

视觉方向为“A2 对话世界志”：深港、雾纸、氧化金属索引和灯金构成潮湿的现场通讯录。顶部 84–104 px 只显示标题、地点/时间、潮位、补给、警戒与唯一 World 按钮；中部为独立滚动时间线；底部 104–152 px 为横向快速回复和自由输入。

玩家消息在右侧并配 32×32 px 头像，NPC 消息在左侧；叙述、检定、数值变化和系统记录拥有不同结构。场景图只在新地点、重要角色、关系转折、关键结果或章节摘要触发，并原位插入导致它发生的回复末尾。未出图时使用港区世界母图，不把图片回写到时间线顶部。

正式海报为 1024×1024 raster key art，只允许英文标题 `SEVENTH DOCK`，标题位于上方 25% 安全区。完整视觉系统见 `doc/visual.md`。

## 3. Game Mechanics

### 3.1 世界状态

- 潮位：初始 28，范围 0–100；场景推进可增加 4–12。70 以上关闭低洼路线，90 以上触发撤离目标，100 且未撤离进入灾难状态。
- 补给：初始 8，范围 0–12；普通移动消耗 1，危险绕行或扎营消耗 2。降至 0 时体力相关检定获得 `-2`。
- 港区警戒：初始 15，范围 0–100；公开冲突增加 10–25，隐蔽失败增加 6–15，成功掩饰减少 5–12。60 以上巡逻事件权重加倍，85 以上公开行动 DC 增加 3。
- 每轮状态变化来自结构化命令并夹紧到声明范围；变化在时间线中紧邻原因显示，不能只让模型在自然语言里声称改变。

### 3.2 角色、关系与检定

- 固定同行者为 Mira、Oren、Sai；每人拥有体力 0–10、压力 0–10 与 0–5 技能。
- 关系事件必须保存人物、关系轴、变化量和来源；普通行动单轴最多变化 8，重大承诺、背叛或救援最多变化 20。
- 只有存在有意义不确定性时使用 d20：`总值 = d20 + 技能 + 情境修正`，情境修正范围 `-3…+3`；DC 5/10/15/20 对应简单/压力常规/困难/绝境。
- 自然 20 为关键成功，自然 1 为关键失败；刷新不得重掷，同轮结果必须产生可见后果。

### 3.3 场景、选择与图片

- 每个决策点提供 2–4 个意图不同的快速行动；自由输入上限 160 字符。
- 场景可包含 1–4 个叙事节拍，高风险场景保持 1–2 个；停在新的真实决策点，不设置“五轮结束”。
- 每次行动拥有稳定 action ID；发送中禁用重复提交，安全重试必须复用相同 ID。
- 每次行动最多触发 1 张 4:3 图片；同一时间只允许一个生图任务。图片失败保留可重试占位，不阻塞下一次行动。
- 只有 HTTPS 用户头像可以作为 `ref_url`。默认 `U` 只用于 UI 回退，没有真实头像时继续 txt2img。

### 3.4 连续存档

- 本游戏使用独立 UUID 和独立本地命名空间，只保存 Seventh Dock 世界，不与模板或其他游戏共享存档。
- 保存地点、时间、目标、三项数值、剧情块、选择、地图、物品、关系、最后语言和远程 chatId。
- 云端优先恢复，localStorage 兜底；只在远程 `message_saved` 或本地完整回合完成后提交世界变化。
- 章节摘要用于压缩已发生事实，但不会覆写人物身份、承诺、死亡、所有权或未解决目标。

## 4. Controls

- 快速回复位于横向滚动容器，使用 `onClick`；滑动浏览不会在 pointer down 时误提交。
- 自由输入常驻底部，允许选择、粘贴和系统输入法；Enter 或 44×44 px 发送按钮提交。
- World、抽屉标签、关闭和图片重试使用 `onClick`；Escape 关闭抽屉。
- 时间线上下滚动是主要阅读手势；玩家主动上滚超过 140 px 后暂停自动跟随，新内容用明确按钮返回底部。
- 390×844 与 320×568 为主验收尺寸；移动端不依赖 hover，焦点始终可见。

## 5. Win / Lose Conditions

没有固定回合胜负。场景成功表示达成当前目标并结算成本；场景失败会失去路线、物品、信任或时间，但故事通常继续。委托完成需要满足 2–4 个必要事实或事件，并展示获得/失去物、关系变化和新地点。

玩家扎营或安全离开时生成当日摘要与下一目标。全队失去行动能力、潮位达到 100 且未撤离，或关键目标永久失败时进入灾难状态；结算必须显示导致结果的事件链，并允许从章节边界开启新时间线，不能静默回滚。

## 6. Sound Effects

- 行动提交：520→410 Hz 三角波，70 ms，音量 0.045，并触发 8 ms 轻震。
- 回复开始：660 Hz 正弦波，55 ms，音量 0.025；每轮最多一次。
- 技能检定：6 个 140–420 Hz 噪声脉冲，总长 380 ms；结果在 420 ms 出现。
- 成功：620/780 Hz 两音，各 90 ms；关键成功增加 980 Hz。失败：260→170 Hz，220 ms；关键失败增加 90 Hz 低频冲击。
- 新地点：480–720 Hz 环境短音，420 ms。图片完成：860 Hz 正弦波，75 ms。
- 首次真实触控前不创建 AudioContext；静音或音频失败不阻断游戏、保存和恢复。
