# 《Seventh Dock》需求文档

## 1. Overview

《Seventh Dock》是一款有状态 AI 驱动的竖屏连续小队冒险：玩家以自己的 AlterU 身份进入不断涨潮的港城，通过对话、调查、检定和资源取舍推进世界。单次游玩目标为 8–12 分钟，但故事不按固定轮数结束，可跨日、跨设备恢复。

核心情绪承诺：世界会记得玩家救过谁、怀疑过谁，以及为了继续前进付出了什么。

主界面只有一条按时间向下生长的剧情流、底部快速回复/自由输入，以及一个收纳人物、地图、背包和日志的“World / 世界”抽屉。支持 AlterU WebView、移动浏览器与分享链接打开后的桌面浏览器；移动端验收 390×844 / 320×568，桌面端验收 1024×768 / 1440×900。支持完整 zh/en 内容；首次语言来自调试覆盖、存档或系统语言，明确使用另一语言回答时自动切换后续界面与回复，历史记录不重写。

当前 AlterU 用户是故事主角。玩家行动与人物页显示其用户名和头像；关键剧情生图可引用公开 HTTPS `head_url`，但头像资料不写入故事存档。

## 2. Visual Design

视觉方向为“A2 对话世界志”：深港、雾纸、氧化金属索引和灯金构成潮湿的现场通讯录。顶部显示标题、地点/时间、潮位、补给、警戒、`Aa` 文字设置与 World 按钮；中部为独立滚动时间线；底部 104–152 px 为横向快速回复和自由输入。`Aa` 提供小/标准/大三档，默认标准正文 17 px，大档 19 px，并在下次打开时保留。

玩家消息在右侧并配 32×32 px 头像，NPC 消息在左侧；叙述、检定、数值变化和系统记录拥有不同结构。场景图只在新地点、重要角色、关系转折、关键结果或章节摘要触发，并原位插入导致它发生的回复末尾。未出图时使用港区世界母图，不把图片回写到时间线顶部。

正式海报为 1024×1024 raster key art，只允许英文标题 `SEVENTH DOCK`，标题位于上方 25% 安全区。完整视觉系统见 `doc/visual.md`。

## 3. Game Mechanics

### 3.1 世界状态

- 潮位：初始 28，范围 0–100；场景推进可增加 4–12。70 以上关闭低洼路线，90 以上触发撤离目标，100 且未撤离进入灾难状态。
- 补给：初始 8，范围 0–12；普通移动消耗 1，危险绕行或扎营消耗 2。降至 0 时体力相关检定获得 `-2`。
- 港区警戒：初始 15，范围 0–100；公开冲突增加 10–25，隐蔽失败增加 6–15，成功掩饰减少 5–12。60 以上巡逻事件权重加倍，85 以上公开行动 DC 增加 3。
- 每轮状态变化来自结构化命令并夹紧到声明范围；变化在时间线中紧邻原因显示，不能只让模型在自然语言里声称改变。

### 3.2 角色、关系与检定

- 固定同行者为 Mira、Oren、Sai；每人拥有体力 0–10、压力 0–10 与 0–5 技能。
- 关系事件必须保存人物、关系轴、变化量和来源；普通行动单轴最多变化 8，重大承诺、背叛或救援最多变化 20。
- 只有存在有意义不确定性时使用 d20：`总值 = d20 + 技能 + 情境修正`，情境修正范围 `-3…+3`；DC 5/10/15/20 对应简单/压力常规/困难/绝境。
- 自然 20 为关键成功，自然 1 为关键失败；刷新不得重掷，同轮结果必须产生可见后果。

### 3.3 危险与遭遇

- 连续 `2–3` 个安全行动后必须出现一次港城威胁；遭遇按“异样征兆 → 封路/追击对峙 → 解决与余波”推进，解决后保留 `1` 个安全冷却行动。
- 威胁池限定为警戒队搜查、潮门突然关闭、低洼通道进水、沉船结构坍塌、走私者伏击和港务机关陷阱。正面战斗不是默认答案，潜行、交涉、绕行、工具和小队分工必须同样成立。
- 解决检定使用稳定 d20，基础修正 `+2`，严重度 1–5 的 DC 为 `9/11/13/15/17`。潮位达到 70、警戒达到 60 或补给低于 3 时严重度至少为 3；潮位达到 90、警戒达到 85 或补给为 0 时直接进入严重度 5 对峙。
- 有代价成功默认使警戒 `+6`；失败默认使警戒 `+12`，关键失败默认使警戒 `+24`。正文若已合法结算潮位、警戒、补给、物品、同伴伤势或路线关闭，本地兜底不重复收费。

### 3.4 场景、选择与图片

- 每个决策点提供 2–4 个意图不同的快速行动；自由输入上限 160 字符。
- 如果远程 AI 把 2–5 个行动写成正文末尾的编号/项目符号列表，系统必须恢复为真实按钮并去掉重复列表；没有可信行动时不得补一个脱离上下文的通用“继续”。阶段小结若同时存在真实行动，优先显示并提交这些行动。
- 场景可包含 1–4 个叙事节拍，高风险场景保持 1–2 个；停在新的真实决策点，不设置“五轮结束”。
- 每次行动拥有稳定 action ID；发送中禁用重复提交，安全重试必须复用相同 ID。
- 场景图采用“AI 提议 + 本地导演兜底”：AI 可为视觉上重要的变化主动提议；AI 未提议时，首次抵达地点、获得稀有/传奇物品、队伍变化和章节节点必须补图，关系、目标或检定变化在距离上一张场景图至少 2 回合时可补图。连续 4 个有效回合没有场景图时，本地导演根据本轮已展示的结果补图；普通寒暄不触发。每次行动最多触发 1 张 4:3 图片，同一时间只允许一个生图任务。图片失败保留可重试占位，不阻塞下一次行动。
- 只有 HTTPS 用户头像可以作为 `ref_url`。默认 `U` 只用于 UI 回退，没有真实头像时继续 txt2img。

### 3.5 连续存档

- 本游戏使用独立 UUID 和独立本地命名空间，只保存 Seventh Dock 世界，不与模板或其他游戏共享存档。
- 保存地点、时间、目标、三项数值、剧情块、选择、地图、物品、已认识角色、当前小队、关系、最后语言和可选远程 chatId。新成员只能与现有小队合并；没有明确离队协议事件时，角色跨场景和重载保持在队。
- 正式入口默认使用 Aigram `game-chat`，每轮携带权威状态与最近 20 个非图片剧情块；带有效 `chat_id` 时才使用实验性服务端连续世界。云端优先恢复，localStorage 兜底；只在 AI 完整响应或远程 `message_saved` 后提交世界变化。
- `story_mode=demo` 只用于三段确定性 QA 演示；内容耗尽后必须明确报错，禁止无限返回通用段落。AI/远程失败不提交行动或数值，并提供 44 px“重试这一步”。
- 章节摘要用于压缩已发生事实，但不会覆写人物身份、承诺、死亡、所有权或未解决目标。

## 4. Controls

- 快速回复位于横向滚动容器，使用 `onClick`；按钮按文字长度在 148–310 px 内自适应，并在窄屏限制为 82vw，长句换行，滑动浏览不会在 pointer down 时误提交。
- 自由输入常驻底部，允许选择、粘贴和系统输入法；Enter 或 44×44 px 发送按钮提交。
- World、抽屉标签、关闭和图片重试使用 `onClick`；Escape 关闭抽屉。
- 时间线上下滚动是主要阅读手势。首次进入锚定第一段背景文字；提交行动时锚定玩家行动，回复完成后锚定本轮第一段结果文字。图片占位、生成完成或失败都不能改变当前阅读位置；用户需要时可用“新内容”按钮返回底部。
- 第二次打开且恢复到 `scene > 0` 的存档时，显示一次恢复弹窗。“继续游戏”关闭弹窗并滚到末尾阅读锚点；“重新开始”必须二次确认，确认后才覆盖本地/Aigram 个人存档并回到开场。
- 390×844 与 320×568 为主验收尺寸；移动端不依赖 hover，焦点始终可见。

## 5. Win / Lose Conditions

没有固定回合胜负。场景成功表示达成当前目标并结算成本；场景失败会失去路线、物品、信任或时间，但故事通常继续。委托完成需要满足 2–4 个必要事实或事件，并展示获得/失去物、关系变化和新地点。

玩家扎营或安全离开时生成当日摘要与下一目标。全队失去行动能力、潮位达到 100 且未撤离，或关键目标永久失败时进入灾难状态；结算必须显示导致结果的事件链，并允许从章节边界开启新时间线，不能静默回滚。

灾难、受伤或小队瓦解不会自动删除存档，也不会强迫玩家回到开场；当前协议没有不可逆的死亡 Game Over，`session_end` 只是可继续的章节记录。玩家可在“世界 → 手记 → 系统”主动选择从头开始：第一次点击展开不可撤销警告，第二次确认才用开场状态覆盖本地与 Aigram 存档，并解除 remote chat 绑定。

## 6. Sound Effects

- 音频全部由 Web Audio 实时合成，不请求网络、不依赖音频文件。音乐/环境/事件三条总线默认相对音量为 0.12/0.10/0.18，总输出峰值不超过 0.24；总活跃声部最多 8 个。
- 主题为 54 BPM、A2=110 Hz、音阶间隔 `0/3/5/7/10`。4 秒平滑噪声循环经 590 Hz 带通形成港风与潮声，并叠加 55 Hz 低频层。紧张度为潮位 45% + 警戒 40% + 补给不足 15%，从下一拍起改变脉冲密度与后续和弦音程。
- 两个连续环境声部之外最多保留 6 个短声部，总上限为 8。行动提交使用 55 ms 带通噪声与 520→410 Hz、75 ms 三角波。
- 检定成功按根音与题材音阶生成三个 160 ms 上行音；失败为 242→159.5 Hz、240 ms 下降音。普通变化为 286→305.8 Hz、120 ms；发现/新地点使用根音、五度、八度的 420 ms 上行音。
- 图片完成使用 760→910 Hz 与 1060→1120 Hz 两层短音；阶段小结播放 700 ms 三音和弦；接口错误使用 140 ms 短下降音。
- 首次真实触控前不创建 AudioContext；顶部 44×44 px 扬声器按钮按实际 `running` 状态显示声音是否开启，启动失败时保持“开启声音”并允许单击重试。移动 WebView 的 `suspended/interrupted` 状态均尝试恢复，静音偏好写入 `localStorage.alteru_story_audio_muted`；音频失败不阻断游戏、保存和恢复。

### 世界实体详情与物品图鉴

- 小队、航图、行囊和手记中的每一行均可点开；详情必须展示当前状态、数值、作用/限制与港城背景。
- 初始三件工具及 AI 后续发现物均保存 `detail/effect/lore/metrics`。玩家第一次打开行囊时，缺图、失败或旧画风物品自动在后台串行显影；首图完成前显示“潮痕正在显影”的港城内说明，不提供手动生成按钮。物品图以本作方形封面为风格参考，和剧情图严格串行、相邻调用至少间隔 3 秒，结果与画风版本随物品存档。
